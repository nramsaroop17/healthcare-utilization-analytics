# Healthcare Utilization & Cost Analytics

I built this project to practice working through a healthcare analytics problem from beginning to end rather than analyzing an already-clean dataset in a single tool.

Using synthetic patient data from Synthea, I built a workflow that takes raw healthcare data through Python for cleaning and validation, PostgreSQL for analysis, and Power BI for reporting.

The final dashboard focuses on three areas: overall healthcare utilization, differences in utilization across patient populations, and 30-day inpatient readmissions.

## Dashboard

### Executive Overview

The first page provides a high-level view of the dataset, including total patients, encounters, claim costs, encounter types, and changes in encounter volume over time.

### Utilization & Demographics

The second page looks more closely at who is using healthcare services. It compares utilization across demographic groups and highlights patients with particularly high encounter volumes.

### Readmissions & Cost

The final page focuses on inpatient readmissions. I created a simplified 30-day readmission measure and used it to compare readmission patterns across patient groups and explore differences in claim costs.

## The Data

I used synthetic healthcare data generated by Synthea. The four datasets used in the project were:

- Patients
- Encounters
- Conditions
- Procedures

The final dataset includes **1,171 patients and 53,346 encounters** across wellness, ambulatory, outpatient, urgent care, emergency, and inpatient settings.

Because the data is synthetic, it contains no real patient PHI.

## My Process

### 1. Data Exploration and Cleaning

I started in Python by examining the structure and quality of the raw CSV files.

This included checking for missing values and duplicates, converting date fields, validating IDs between datasets, calculating patient age and encounter duration, and looking at the distributions of encounters and costs.

After validating the data, I created cleaned versions of each dataset for loading into PostgreSQL (Processed).

### 2. PostgreSQL and SQL Analysis

I created a PostgreSQL database with separate tables for patients, encounters, conditions, and procedures. Primary and foreign keys were used to maintain the relationships between the datasets.

From there I used SQL to ask and answer the following:

- Which encounter types are most common?
- Which patients have the highest overall utilization?
- How frequently are patients using emergency and inpatient services?
- How does utilization differ across demographic groups?
- Which encounter types account for the most claim costs?
- How often does another inpatient encounter occur within 30 days of a previous discharge?

The SQL portion of the project uses **joins, CTEs, CASE expressions, conditional aggregation, date calculations, FILTER, and window functions**.

I also created three views specifically for reporting in Power BI:

- vw_patient_utilization
- vw_encounter_summary
- vw_readmission_detail

Keeping much of the transformation and business logic in SQL allowed Power BI to work from reporting-ready datasets instead of recreating the analysis inside each visual.

### 3. 30-Day Readmissions

One of the areas I wanted to explore more deeply was inpatient readmission.

I used SQL's LAG() window function to find each patient's previous inpatient discharge:

LAG(stop_time) OVER (
    PARTITION BY patient_id
    ORDER BY start_time
)


I then flagged a subsequent inpatient encounter when it occurred within 30 days of that previous discharge.

This gave me a reusable readmission indicator that I could bring into Power BI and analyze by age, gender, and claim cost.

This is a simplified readmission definition created for the project and is **not intended to reproduce an official CMS readmission measure**.

### 4. Power BI

I connected Power BI directly to the PostgreSQL reporting views and built a 3-page interactive report:

**Executive Overview**
- Total patients and encounters
- Total and average claim costs
- Encounters by type
- Encounter volume over time
- Claim costs by encounter type

**Utilization & Demographics**
- Utilization by gender and race
- Emergency utilization by age group
- High-utilization patient ranking
- Interactive demographic and encounter filters

**Readmissions & Cost**
- 30-day readmission count and rate
- Readmission rates across demographic groups
- Average inpatient claim costs
- Cost comparison between readmitted and non-readmitted encounters

## What I Took Away From the Project

The most useful part of this project was working across the full analytics workflow instead of treating Python, SQL, and Power BI as separate exercises.

It taught me to think about how raw data should be validated before analysis, how tables should relate to one another, which calculations belong in SQL versus the business intelligence layer, and how analysis can be turned into a dashboard that someone can actually use.

It also reinforced the importance of checking the limitations of the underlying data. In this case, Synthea's costs are synthetic and show patterns that shouldn't be interpreted as real healthcare pricing. The dashboard is therefore meant to demonstrate the overall workflow, not make real-world claims.
